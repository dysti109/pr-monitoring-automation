# OAuth 기반 PR 모니터링 운영 구조

이 문서는 RSS 리더와 Codex CLI를 결합한 로컬 PR 모니터링 구조를 설명한다. 실제 검색 대상, 검색어, 피드 주소와 이메일 수신자는 공개 코드에 두지 않고 로컬 설정으로 관리한다.

## 1. 역할과 데이터 경계

| 구성 요소 | 역할 | 자격 증명 |
| --- | --- | --- |
| Papr 데스크톱 앱과 CLI | RSS 구독, 기사 저장·검색, 읽음 상태 관리 | 로컬 데이터베이스 |
| Codex CLI | 공개 웹 후보 검색, 원문 확인, 분류·분석과 브리프 작성 | 사용자가 로그인한 ChatGPT OAuth |
| 모니터링 지침 | 수집·분류·평가 절차와 산출 형식 정의 | 텍스트 지침 |
| 로컬 설정 파일 | 실제 기업명, 브랜드, 키워드, RSS, 이메일 주소 보관 | Git에서 제외 |

공개 기사 제목과 본문은 분석 시 모델에 전달될 수 있다. 비공개 내부 자료와 자격 증명은 분석 프롬프트에 넣지 않는다. OAuth 자격 증명은 사용자 프로필에 두고 저장소에 커밋하지 않는다.

## 2. 수집 흐름

1. 로컬 설정에서 주 대상, 지정 대상, 검색어와 공식 피드를 읽는다.
2. Google News RSS와 접근 가능한 웹 검색으로 후보를 찾는다.
3. 설정된 경우 사전 검색을 세 회차로 나눠 회사·브랜드, 제품·서비스·고객·계약어, 표기 변형·구체 검색어 순으로 후보를 누적한다.
4. 최종 단계에서 네이버 뉴스와 접근 가능한 일반 웹 검색을 교차 확인한다.
5. 원 매체 페이지에서 제목, 발행 시각, 관련성, 매체와 기자 정보를 검증한다.
6. 같은 URL은 제거하고, 동일 사건의 별도 기사는 한 이슈로 묶어 대표 기사와 추가 보도를 연결한다.
7. 결과를 분석하고 보고서와 메일을 생성한다. 수집 한계와 원문 접근 오류는 결과에 기록한다.

RSS 결과는 발견 후보일 뿐이다. 원문이나 발행 시각을 확인하지 못한 항목은 확인 완료로 취급하지 않는다.

## 3. 브라우저 미리보기

Vite 개발 서버의 브라우저 미리보기는 Papr 데스크톱 앱 없이도 화면과 설정된 RSS 대상의 기사 목록을 확인하기 위한 기능이다. 미리보기 RSS API와 최종 PR 분석은 서로 다른 경로를 사용한다. 미리보기의 기사 수는 전체 수집·분석 결과를 뜻하지 않는다.

브라우저 모드에는 네이티브 데이터베이스와 일부 데스크톱 명령이 연결되지 않을 수 있다. 읽음 상태 등은 영구 저장되지 않을 수 있으며, 원문 검증·분석 기능은 최종 PR 분석 경로에서 수행한다.

## 4. 공개 저장소 운영 원칙

- 공개 예시 파일에는 자리표시자만 둔다.
- 실제 수신 이메일, SMTP 앱 비밀번호, 검색 대상과 검색어, 공식 RSS 주소는 로컬 설정에 둔다.
- 실행 기록, 수집 캐시, 누적 보관 데이터, 기자 연락처와 개인별 분석은 저장소에서 제외한다.
- 공개 가능한 수집 기준은 docs/collection-criteria.md에서 관리한다.
- 인증 오류가 발생하면 별도 API 키를 저장하지 말고 사용자 OAuth 로그인 상태를 확인한다.
